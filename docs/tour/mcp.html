MCP is the one place where edgar runs somebody else's code and trusts somebody else's schema. Two rules shape everything on this page. A configured server costs nothing until one of its tools is actually called (ADR-0047), because a cold edgar -p must still answer inside the startup budget (NFR-1). And a turn never opens a browser: signing in is a command a human runs, not something the loop decides to do (ADR-0048).

Stage 1. Servers that are not running about 15 minutes

1Lazy start

tools/mcp/client.py tools/mcp/stdio.py tools/mcp/http.py

Look for: PROTOCOL McpError Server McpTool servers discover close Stdio Http

Start in client.py and find the moment the server is actually started. It is not in servers, which only reads config and builds handles; it is inside the tool's own call path. Everything before that point runs with no subprocess, no socket and no httpx import — the startup budget again (ADR-0012), which is also why the transports live in two small modules imported only when one is chosen.

discover is the handshake: initialize, check the protocol version against PROTOCOL, list the tools, and cache the result under a digest of the server's own configuration, so changing a command or a URL invalidates it and nothing else does. A server that fails is remembered as failed for the rest of the session rather than retried on every call — read that bit and decide for yourself whether you would have written it that way.

The two transports are deliberately boring and deliberately different. Stdio spawns a process, writes newline-delimited JSON to it, and drains stderr on a thread so a chatty server cannot fill a pipe and deadlock the harness. Http speaks Streamable HTTP: one POST that may answer with JSON or with an SSE stream, so it has to parse events as well as bodies. Both raise the same McpError, which is what lets the caller above them not care which one it got.

close is worth a minute. Servers are children of this process, and the shutdown path is explicit rather than left to the garbage collector, because a stdio server that is never reaped is a hung terminal.

Take with you: "lazy" here is not an optimisation bolted on afterwards. It is the reason the config format carries a command and not a connection.

2Deferred schemas

tools/mcp/schema.py tools/builtin/tool_search.py

Look for: to_schema to_result hints tool_name ToolSearch FOUND RESERVE

Thirty servers with twenty tools each would put six hundred JSON schemas above the cache breakpoint, and most of them would never be called. So the prompt carries the names, and tool_search hands back the full schemas for the handful the model asks about. The deferred tools become callable from that point in the session, which is the whole trick: the model discovers a tool the way a person would, by looking it up.

RESERVE is the budget line — how much of the window this is allowed to take — and FOUND is the wording the model gets back, written so the next step is obvious without another round trip. Notice that the results are ordinary tool output, not a special channel.

schema.py is the border guard. tool_name namespaces a server's tool so two servers cannot collide and a server cannot claim a built-in name; to_schema accepts only what the harness can validate and drops the rest; to_result turns whatever came back into ordinary content blocks. Everything here is written on the assumption that the server is not malicious but is certainly careless.

Stage 2. Signing in about 15 minutes

3The loopback dance

auth/oauth.py auth/store.py

Look for: pkce Loopback listen visit post SERVICE available read write erase

OAuth 2.1 with PKCE, no client secret, on a loopback port the harness picks itself. pkce makes the verifier and its challenge; Loopback is a one-request HTTP server whose only job is to catch the redirect, check the state value, and close. Read listen with an eye for what it refuses: a mismatched state, a second request, a wait that has run out.

visit is the only place in edgar that opens a browser, and it is reached from a command, never from a turn. When there is no browser it prints the URL and waits, which is the same flow over SSH.

store.py is thirty lines that decide where a token lives. keyring is an optional extra, imported inside the function, and available answers honestly when it is missing rather than silently writing a token to a file. erase exists so that logging out really removes it.

4Two kinds of sign-in

auth/keys.py auth/mcp.py

Look for: login logout account sign_in CLIENT SCOPES token _metadata _endpoints _register

keys.py is edgar login PROVIDER: a key or a token for a provider, resolved in a fixed order — the environment first, then what a previous sign-in stored, then api_key_command (ADR-0044). The order is the interesting part: an environment variable always wins, so a stored token can never quietly override what you exported in this shell.

mcp.py is edgar mcp login NAME, and it is longer because the server has to be discovered before it can be talked to. _metadata and _endpoints follow the protected-resource and authorization-server documents; _register does dynamic client registration when the server offers it, since there is no secret to hand out in advance. token handles both the first exchange and the refresh, and a refresh that fails deletes the stored token instead of retrying forever.

sequenceDiagram
    participant H as a human at a terminal
    participant E as edgar mcp login
    participant S as the MCP server
    participant A as its authorization server
    H->>E: edgar mcp login notion
    E->>S: GET the protected-resource metadata
    S-->>E: which authorization server to use
    E->>A: register this client, if it is offered
    E->>H: open this URL (loopback redirect waiting)
    H->>A: sign in and approve
    A-->>E: code, on the loopback port
    E->>A: code + verifier
    A-->>E: token
    E->>E: store it in the keyring

Take with you: the harness holds no client secret anywhere, and the token never passes through the model's context.

Before you go: a server you configured returns 401 in the middle of a turn. What does the model see, what does the human see, and what has edgar deliberately not done?
