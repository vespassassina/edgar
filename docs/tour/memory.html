Read stop 15 and stop 17 of the Core tour first: memory hangs off the prompt builder's pinned sections and off the append-only session file, and neither changes shape to make room for it.

The claim to test as you read: an active fact comes only from text a human typed, or from an error record the harness computed itself. Everything else — the model's own remember call included — can become a pending fact at most, and a pending fact is never in the prompt and never in the search index (MEM-8, MEM-9, ADR-0017). It is enforced by what each function accepts, not by a filter you could forget to call.

Stage 1. The boundary about 15 minutes

1What becomes a fact

memory/store.py memory/redact.py

Look for: add confirm _Op pinned overlap NEAR redact ASSIGNED

The whole boundary is one line inside add: a fact is active only when its provenance is "user" and nothing already active says nearly the same thing. overlap is the word-level Jaccard measure and NEAR the threshold, so even a human's near-duplicate lands pending, carrying the id of the fact it would supersede — because a contradiction is for a person to settle, not for the newest writer to win (MEM-10).

Read _Op next, and notice what it does not do. It never rewrites a fact's text: an edit is a new fact plus a supersedes link, and every confirm, forget and replace is a status change logged under one operation number, which is the only reason edgar memory undo can always put things back. The index invariant is worth finding for yourself: the same function drops the fact from both FTS5 tables and re-inserts it only when the new status is exactly "active", so "a pending fact can never be recalled" is true by construction rather than by a check somewhere downstream.

pinned is the one read that writes: it bumps each returned fact's use count. The set it returns is chosen once at session start and sits above the cache breakpoint (MEM-6, CTX-17), which is why a fact you add now first shows up in the next session — a surprise worth understanding rather than fixing.

redact.py is twenty-five lines and runs on the way in and on the way out. Whole-secret shapes go first and vanish entirely; ASSIGNED then handles token = …, keeping the name and dropping only the value, so the fact still reads. The docstring is honest that this is best-effort: the real guarantee is that secrets come from the environment (CFG-6), not that a regex catches them.

Take with you: the boundary is a type signature, not a filter. Nothing on this path accepts tool output, error text, fetched content or an attached file in the first place.

Stage 2. Getting it back about 10 minutes

2Recall, without an embedding model

memory/retriever.py memory/recall.py

Look for: Retriever Hit retriever Fts5Retriever search index SNIPPET

retriever.py is one of the six ports (ADR-0022): a Protocol with a single method, so a vector or graph plugin never has to import anything from edgar. The factory resolves the built-in name inside the function — the startup budget again — and otherwise looks in an entry point group, failing with a message that lists what is actually installed.

Core carries no embedding model on purpose (ADR-0024). Fts5Retriever runs the same query twice, once over a porter-stemmed index and once over a trigram one, and merges them so a porter hit always beats the trigram hit for the same item. That is what lets a fragment like config/lo find a path, which stemming alone never would.

index is where the care is. It seeks to a stored byte offset, reads the rest of the session file, and then throws away everything after the last newline, because the file is append-only and a line may still be half-written. It indexes only text blocks that are not attached, so tool results and attached files stay out of the index exactly as they stay out of the facts.

3The markdown round trip

memory/markdown.py cli/memory.py

Look for: render parse edit HEADER command said _review

Facts are rendered to markdown, opened in your editor, and read back: what you save is the new active set, so deleting a section means everything in it is gone rather than unchanged. parse strips HTML comments before it reads anything, which is how HEADER can explain the contract in the buffer without becoming a fact.

Two details in edit are worth the detour. The editor setting is split with shlex so code --wait works, and it is still never run through a shell; and the program is resolved with which first, which is what makes code.cmd work on Windows. A non-zero exit from the editor changes nothing at all.

In cli/memory.py, said exists so that edgar memory add and /remember word the same outcome identically, including the pending case. _review is the human confirmation gate, and its default is the safe one: the prompt is [y/N], and no terminal to ask means the facts stay pending rather than being guessed either way.

Stage 3. Branching a session about 10 minutes

4Forks and saves

storage/transcript.py

Look for: fork chain _upto save _inline _scrub forks adopt

M7 added three moves to sessions and broke none of Core's append-only rule (ADR-0046). A fork costs exactly one line: a new file whose second line names its parent and a turn. The parent is never copied and never touched. chain walks up while the second line is a fork record, then reassembles downwards with a loop, not recursion, and _upto finds the cut by looking for the turn's own finish record.

flowchart LR
    p[("parent.jsonl
head · turns 1-9")] -->|"read up to turn 4"| c
    c[("fork.jsonl
head · fork line · its own turns")] --> v["the view
chain(path)"]
    v -->|"save: inline blobs, then redact"| out[("one portable file")]
    out -->|adopt| new[("a new session of this project,
with a new id")]

save is the opposite move: the chain flattened into one file that travels. _inline reads spilled tool output back off disk so the file is self-contained, and _scrub then walks the whole JSON structure — with an explicit stack, not recursion — redacting string by string, deliberately, so a pattern can never match across JSON syntax and corrupt the shape. Notice that the original session file is never rewritten by any of this.

forks is the reverse lookup and shows what the layout buys: it reads exactly two lines of each sibling file to find the children of one session. adopt deliberately makes a loaded file a new session of this project rather than a fork, so a file someone sent you can never claim a parent you do not have.

Before you go: trace one path by hand. The model calls remember mid-turn — where does that text end up, what can retrieve it, and what exactly has to happen before it is ever in a prompt?
