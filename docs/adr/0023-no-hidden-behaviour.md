# ADR-0023 — No hidden behaviour: no implicit hosts, the prompt is a file, the prefix is stable

**Status:** Accepted · 2026-09-13

## Context

The most heated findings in the field review (docs/research/hn-2026-09.md) were
about things harnesses do that users did not ask for and could not see:

- Session titles generated by a hosted model even when only a local model was
  configured; configuration fetched from the web by default; a login flow running a
  shell command supplied by a remote website
- System prompts that change between releases without notice, run to tens of
  thousands of tokens before the user's prompt, and carry style opinions the user
  never chose ("no comments")
- The current date and re-read instruction files in the system prompt, breaking
  the prompt cache on every turn and multiplying cost
- Reasoning hidden from the user by default

edgar's principles already say "the mechanism is visible" and "fail loudly". This
ADR turns them into rules a test can check.

## Options

**A. Principle only.** Leave it to review discipline.

**B. Five checkable rules**, each with a test or a command that shows compliance.

## Decision

Option B.

**1. No implicit models, hosts or telemetry** [PRV-15]. Every model request goes to
a model named in config or on the command line. Auxiliary roles (compactor,
controller, condenser) default to the main model, never to a model the user did not
name. edgar contacts no host except those named in config and those reached by a
tool call the policy allowed. There is no telemetry, update check or remote
configuration, ever. `edgar doctor --network` lists every host the current config
can contact and why.

**2. The prompt is a file with a budget** [CTX-16, NFR-13]. The base system prompt
ships as `prompts/system.md` (and `prompts/compact.md` for small models, PRV-17),
readable with `edgar prompt show`. A project replaces it with
`.edgar/prompts/system.md`, which is a control file. The shipped prompt describes
the harness, the tools and the safety rules; it carries no style opinions about
comments, emojis or commit messages, which belong in the user's instruction files.
CI measures it: base prompt ≤ 1,500 tokens, all Core tool schemas together ≤ 2,500.
Every change to a shipped prompt is listed in the changelog.

**3. The prefix is byte-stable** [CTX-17]. Nothing above the cache breakpoint
(CTX-1) changes within a session. The date, time, git status and other volatile
values go in the current turn. Instruction files are read once at session start
(CFG-8). A test asserts that the serialised prefix is byte-identical across every
request of a session until a compaction.

**4. Reasoning is visible when the provider exposes it** [CLI-21]. `--show-thinking`
and `/thinking` render reasoning deltas; `--json` and `--events` include them
when requested. Where a provider only returns a summary or nothing, edgar says so
rather than pretending.

**5. Nothing from a remote source is executed.** No remote configuration, no
provider-supplied commands in auth flows (credentials come from env or keyring),
no automatic updates. `edgar ext add GIT_URL` copies files the user asked for, and
their executable parts still need project trust (PERM-13).

## Consequences

- **The pitch becomes checkable:** "edgar never talks to a host you did not
  configure" is backed by a command and a test, not a promise
- **Cheaper sessions:** a small prompt plus a stable prefix means most requests hit
  the provider's cache
- **Opinions move to where users control them**: `AGENTS.md`, skills, hooks
- **Load-bearing:** auxiliary roles default to the main model. A future "helpful"
  default that routes titles or summaries to a cheaper hosted model breaks rule 1
  for local-only users, silently
- **Load-bearing:** the prefix test. Without it, one `datetime.now()` in the builder
  quietly doubles every user's bill

## Rejected alternatives

**A (principle only)** is rejected because every harness in the review has the
same principle in its README and still shipped the behaviour above.

**Anonymous usage telemetry, opt-in** was considered for guiding development. It
is rejected: the eval set and GitHub issues are enough signal, and "no telemetry,
ever" is a sentence people can trust without reading the code.
