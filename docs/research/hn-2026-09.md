# Field review: what Hacker News says about agent harnesses

September 2026. The evidence behind spec revision v0.4 ([DECISIONS.md](../DECISIONS.md)).
Comments are paraphrased, not quoted.

## Method

- Searched Hacker News through the Algolia API for 37 queries: the harnesses
  themselves (Claude Code, OpenCode, Codex CLI, Gemini CLI, Aider, Pi, Crush, Letta
  Code, Plandex, Amp), the formats (AGENTS.md, Agent Skills, MCP), and the topics
  (memory, context, sandboxing, local models, supply chain).
- Picked 43 threads with more than 30 comments that were about harness design or
  use, and read them in HN's own ranked order. Three were rate-limited; **40
  threads and 11,647 comments** made it into the analysis.
- Read the top-ranked comments of every thread in full, then counted how often
  each theme came up across all comments with keyword patterns.

**Caveats.** Theme counts measure how often something is discussed, not how many
people want it. The sample is weighted toward threads that were chosen for a topic
(two MCP threads inflate the MCP count, for example). HN skews toward experienced,
opinionated developers. That skew suits edgar's primary audience.

## What people say

### What existing tools get wrong

1. **Hidden behaviour.** The strongest reaction in the OpenCode threads was to
   things users did not configure: session titles generated by a hosted model even
   when only a local model was set up, configuration fetched from the web by
   default, and a login flow that ran a shell command supplied by a provider's
   website. In the Claude Code threads it was system prompts that change between
   versions without notice, reasoning hidden by default, and a mode instructing the
   agent to hide AI involvement in commits. People reverse-engineer prompts and
   patch them with `sed` after every update.
2. **Bloat and churn.** OpenCode is described as effective but vibe-coded, with a
   release cadence that breaks workflows. A recurring migration story is Claude
   Code or OpenCode, then Pi, then writing your own. The appetite for small,
   readable harnesses is real, and "write your own on top of a minimal one" is a
   common recommendation.
3. **Token waste.** A 33k-token preamble before the user's prompt, subagents that
   spend a whole budget in parallel, the current date in the system prompt
   breaking the prompt cache every turn, and instruction files re-read every turn.
   Cost comes up constantly and prompt-cache discipline is poorly understood.
4. **Vendor lock-in.** Subscriptions tied to one vendor's harness, bans for using
   them elsewhere, legal action against an open-source harness. Users want the
   harness and the model vendor decoupled.
5. **Security posture.** Permissive defaults, an unauthenticated RCE that went
   unanswered because there was no security contact, malware in the most
   downloaded skill of a skill hub, and a compromised release of a popular
   provider-abstraction library through its CI pipeline.
6. **TUIs that fight the terminal.** Flicker, broken scrollback, text that cannot
   be selected, apps that take over the screen and leave nothing behind. Several
   people want an agent that behaves like a command in a normal shell session.
7. **Skills that do not fire.** In one published eval, the agent never invoked the
   available skill in over half the cases, and a docs index in AGENTS.md did
   better. Commenters trace it to descriptions that say what a skill is rather
   than when to use it, and to leaving the decision entirely to the model.

### What people need

1. **Plans and todo lists.** Plan-then-execute and a live todo list are the most
   praised working practices. People keep `plan.md`, changelog and working-memory
   files by hand because the built-in ones do not survive compaction or sessions.
2. **Context control.** Trees and forks of a conversation ("side quests" that bring
   back only the good part), elided tool output, and knowing what is in the prompt.
3. **Isolation that is not theatre.** Many run agents in containers, VMs or a
   separate Unix user. Codex's OS sandbox is cited as a counterexample to "security
   makes agents useless". Agents in sandboxes forge lockfile hashes, append
   `|| true` to hide failures, and rebuild networking to get around restrictions,
   so anything the agent reports about its own success is suspect.
4. **Local models that work.** Forge shows guardrails, tool errors returned to the
   model and retries taking a small model from roughly half to nearly all tasks
   done. Local users care about speed and short contexts.
5. **Credentials kept away from the model.** The strongest argument for MCP over
   CLIs is that a server can hold the token and expose fixed operations. The
   strongest argument against MCP is context bloat and a protocol layered over
   APIs that already exist.
6. **Memory that is small and editable.** A curated `MEMORY.md` read at session
   start is enough for many. Exact-string search over past sessions (error
   messages, function names, flags) is more useful than semantic search. Memory
   the user cannot see or edit poisons context.

### What people praise

- **Minimalism** (Pi, the 200-line agent, Codex CLI's Rust implementation)
- **Open, model-agnostic harnesses** that accept any OpenAI-compatible endpoint
- **Tests and compilers as feedback**: letting the agent try and verify rather than
  reason at length
- **Maintainers who own mistakes quickly and publicly**

## On memory specifically

The memory threads are the most sceptical in the sample. Several points recur:

- Auto-extracted facts degrade. A mem0 user gave up after the database filled with
  incomplete and wrong sentences. ChatGPT's memory is described as filling with
  irrelevant or incorrect entries.
- Contradiction detection by similarity does not work. The author of a memory
  database admitted its consolidation merged two unrelated executives because the
  sentences looked alike, and commenters argued that contradictions depend on
  context no embedding captures.
- Embeddings cost what a lightweight tool cannot pay: hundreds of megabytes of
  model, or a network call to an embedding API, plus nondeterministic results. One
  author chose exact-token search for exactly this reason.
- Claude Code and Codex use grep, not embeddings. Models are trained so heavily on
  grep that they distrust other search tools' results and re-read anyway.
- Where embeddings do help: synonyms and mixed languages over large document sets.
- The "graph" in the most-liked memory tool (Beads) is a dependency graph of tasks,
  not a semantic knowledge graph. Structure helped; semantics did not.

## What edgar takes from this

Decisions D18 to D33 in [DECISIONS.md](../DECISIONS.md). In short:

| Finding | Response | Where |
|---|---|---|
| Hidden calls, hidden prompts, cache-busting prompts | No implicit models or hosts, no telemetry, the prompt is a versioned file with a token budget, the prefix is byte-stable | ADR-0023 |
| Bloat and churn | Per-tier size budgets already; ports keep the core small and swappable | ADR-0015, ADR-0022 |
| Vendor lock-in | API keys and any compatible endpoint; provider plugins | ADR-0020, ADR-0022 |
| Plans and todos lost in compaction | `todo` tool and plan mode as pinned session state; forks | ADR-0025 |
| Isolation | Sandbox backends as a port (v1) | ADR-0022 |
| Agents faking success | The verify gate runs the check itself, as already specified | ADR-0014 |
| Small local models | Deterministic tool-call repair, a compact prompt profile | PRV-16, PRV-17 |
| Skills not firing | Deterministic skill triggers, description lint | SKL-17 |
| MCP context bloat | Deferred tool schemas behind a search tool | TOOL-15 |
| Supply chain | Trusted publishing, hash-pinned lockfile, a security contact from M0 | NFR-14 |
| TUIs fighting the terminal | Native scrollback, no alternate screen | CLI-23 |
| Memory scepticism | Stay lexical; a retriever port for those who want vectors | ADR-0024 |

**Not taken:** piggybacking on vendor subscriptions (a terms-of-service fight
edgar should not pick), a skill or extension hub (the malware thread is the
reason), automatic memory injection, flashy TUIs, and an LLM router.
